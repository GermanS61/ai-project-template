# PROJECT INIT PROMPT

Используйте этот prompt после создания нового репозитория из шаблона и первоначального заполнения `PROJECT_BOOTSTRAP.md`.

```text
Ты начинаешь новый программный проект в этом GitHub-репозитории.

Сначала прочитай и соблюдай `AGENTS.md`.

Затем изучи `PROJECT_BOOTSTRAP.md` и текущие файлы репозитория. Не начинай сразу писать большой объём production-кода.

Твоя задача на этапе инициализации:

1. Восстановить точную цель проекта, пользователей, основной сценарий и ограничения.
2. Найти противоречия, критические неизвестные и скрытые предположения.
3. Если неизвестное не блокирует безопасную архитектуру — пометь его `TBD`, сделай разумное предположение и продолжай. Критические продуктовые развилки вынеси на решение владельца проекта.
4. Определить минимальный MVP.
5. Определить Working Skeleton — самый маленький полноценный end-to-end механизм, который можно запустить и проверить.
6. Спроектировать модульные границы так, чтобы проект мог работать самостоятельно, быть встроен в большую систему и подключать внешние компоненты через явные контракты, если это соответствует задаче.
7. Не создавать гипотетические abstraction layers без реальной потребности.
8. Обновить `ARCHITECTURE.md`.
9. Разбить работу на проверяемые этапы в `PROJECT_PLAN.md`. После каждого этапа проект должен оставаться работоспособным.
10. Обновить `ROADMAP.md`: в roadmap включать только принятый scope. Не превращать идеи автоматически в обязательства.
11. Если существенное архитектурное решение требует фиксации — создать ADR в `docs/decisions/`.
12. Сформировать первоначальные GitHub Issues: implementation tasks отдельно, Feature Requests/Research отдельно.
13. Для каждой задачи определить acceptance criteria и способ проверки.
14. Предложить Stage 0 / Stage 1 и только после формирования структуры приступить к Working Skeleton.

Перед кодированием покажи краткое резюме:
- что мы строим;
- MVP;
- Working Skeleton;
- архитектурные модули;
- этапы;
- ключевые риски;
- вопросы, действительно требующие решения владельца.

После этого работай через отдельные ветки и PR согласно `CONTRIBUTING.md` и `AGENTS.md`.
```
