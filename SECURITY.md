# SECURITY

## Базовые правила

- не коммить secrets, tokens, `.env`, private keys и production credentials;
- если проект использует dotenv-конфигурацию, поддерживайте `.env.example` с безопасными пустыми placeholders и без рабочих credentials;
- секреты должны храниться в secret manager / GitHub Secrets / другом утверждённом механизме;
- перед разрушительными изменениями данных или инфраструктуры должен существовать rollback/backup plan;
- минимизируйте права внешних integrations.

Не публикуйте в открытом репозитории реальные внутренние адреса, способы доступа, чувствительные topology details или incident data. Используйте безопасные aliases и ссылки на систему с подходящим контролем доступа.

## Скомпрометированные секреты

Ключ или token, попавший в чат, лог, коммит, скриншот или вывод агента, считается скомпрометированным. Его необходимо отозвать или ротировать, проверить последствия и зафиксировать инцидент в контролируемой системе без повторного сохранения значения секрета.

## Изменение конфигурации

Перед изменением конфигурации определите её источник истины и создайте подходящую платформе версионированную rollback-копию без перезаписи предыдущей. Проверьте копию и способ восстановления. Для IaC или immutable infrastructure изменяйте декларативный источник вместо ручного редактирования сервера.
