# Feature Evaluation

Идея не становится задачей автоматически. Оценка нужна, чтобы руководитель проекта и разработчик могли сопоставлять пользу функции с ценой её реализации и сопровождения.

## Базовые факторы

Оценка 1–5 или `TBD`:

| Фактор | Смысл |
|---|---|
| User Value | насколько функция решает реальную проблему |
| Expected Demand | ожидаемая частота/ширина использования |
| Strategic Fit | соответствие цели проекта |
| Implementation Cost | сложность разработки и тестирования |
| Maintenance Cost | долгосрочная цена поддержки |
| Architecture Risk | риск усложнения, coupling и migration |

Не используйте сумму баллов как автоматическое решение. Небольшая критичная функция может быть важнее большой популярной идеи, а высокая архитектурная цена может перевесить краткосрочную пользу.

## Возможные решения

- **Ready** — Issue прошёл triage, входит в утверждённый scope и может быть запланирован;
- **Deferred** — идея сохранена, но сейчас преждевременна;
- **Rejected** — не соответствует целям или цена выше пользы;
- **Needs Research** — требуется spike/research перед решением.

Решение хранится в single-select поле `Status` GitHub Project. Причина `Deferred` и `Rejected` должна сохраняться в Issue.
