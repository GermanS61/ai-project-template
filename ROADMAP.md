# ROADMAP

> Roadmap содержит **принятые** направления развития. Идеи и предложения, которые ещё оцениваются, остаются GitHub Issues и не должны создавать впечатление обязательства. Канонический workflow хранится в поле `Status` GitHub Project; в roadmap попадает только scope со статусом `Ready` или явно утверждённый владельцем проекта.

## Deferred / Rejected

Не дублировать здесь весь backlog. Сохранять соответствующие Issues со статусом и причиной решения.

## Правило перехода

```text
Triage
↓
Evaluation
↓
Ready
↓
Roadmap
↓
Implementation
```

`Feature Request` не попадает в roadmap автоматически. Labels классифицируют Issue и не заменяют Project `Status`.
